# 3D 圖表改用 GPU 壓縮貼圖？（2026-10 評估）

## 現況（41 張圖表，webp）

| | 下載量 | 顯示記憶體（解碼成 RGBA8） |
|---|---|---|
| 全部圖表 | 24 MB | 312 MB |
| 一般關卡，2 倍解析度（例：第 3 關） | 8.9 MB | 126 MB |
| 一般關卡，一般解析度 | 4.5 MB | 52 MB |

每關只載入用得到的圖表，換關時釋放（`LevelScene` preload）。
2 倍解析度只開給記憶體 ≥ 4 GB 的裝置（`wantHdSheets`），當機後自動降回省電畫質。

## 壓縮格式的取捨

ASTC 4×4、ETC2 RGBA、BC3 都是每像素 1 byte，顯示記憶體是 RGBA8 的 1/4（上面那關 126 MB → 32 MB）。代價：

- **下載變大約 3.6 倍**：這些格式本身不壓縮（一關 8.9 MB → 約 32 MB；gzip 後約 20～25 MB）。
- **一份不夠**：iPhone / 新 Android 用 ASTC、舊 Android 用 ETC2、電腦用 BC3，三份都要放，網站和 APK 多約 230 MB。
- Phaser 3.90 的 `load.texture` 只吃 KTX v1 / PVR，不支援 Basis Universal（KTX2）。
  用 KTX2（ETC1S / UASTC）可以只放一份、下載接近 webp，但要自己寫轉碼載入器（WASM 轉碼器約 200 KB），
  而且 ETC1S 在粗描邊和半透明邊緣會有色塊，UASTC 檔案又比 webp 大 2～3 倍。

## 結論

**先不換。** 目前顯示記憶體的壓力已經靠「每關只載用得到的圖 + 依裝置記憶體決定解析度 + 當機自動降畫質」控制住，
換壓縮貼圖會讓第一次進關的下載變成好幾倍，對朋友用手機網路測試反而更糟。

之後如果出現下列情況再重新評估（優先試 KTX2 + UASTC + 自寫載入器）：
- 中階手機（3～4 GB）回報閃退，且省電畫質也撐不住；
- 想讓 2 倍解析度開給所有手機；
- 上架 App 後改成整包下載（不在乎首次下載量）。
